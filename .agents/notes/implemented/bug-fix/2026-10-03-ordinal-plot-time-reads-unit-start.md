# Agent Note: 剧情时间里的序数单位读作该单位的起点

Status: implemented

## Problem

`index_normalize.parse_plot_time` 原先把序数词"第"直接去掉再读（见 `2026-10-02-understanding-index-normalization.md`），`第3分钟` 读成 `03:00`。"第3分钟"说的是第三分钟这一段，也就是 `02:00`–`03:00`；读成 `03:00` 落在这一段的末尾之后，写稿 Agent 按它找画面会晚整整一分钟，`第1分钟` 更会被读成已经过了开头的 `01:00`。

## Decision

- 整个时间只是"第 + 整数 + 单个单位"（`第N小时` / `第N分钟` / `第N分` / `第N秒`，后面可以跟"左右""前后"或区间分隔符）时，读作该单位的起点 `(N-1) × 单位`：`第3分钟` 读作 `02:00`，`第1分钟` 读作 `00:00`，`第95秒` 读作 94 秒，`第2小时` 读作 `1:00:00`。`第0分钟` 这类从 0 数的写法读作 0，不当成负数丢掉。
- 秒与分、小时用同一条规则：序数总是指第 N 个单位这一段，统一读起点；对秒来说差 1 秒，远小于剧情时间的精度，换来的是没有例外。
- "第"后面是复合时间或时刻时仍只去掉"第"：`第3分20秒` 读作 `03:20`，`第01:20` 读作 `01:20`；`第2.5分钟` 这种带小数的写法不是序数，按 2.5 分钟读。
- 实现在 `_plot_time_text`：先用 `_ORDINAL_UNIT_RE` 把序数单位改写成秒数，其余情况再由 `_ORDINAL_RE` 去掉"第"。`tests/understanding/test_consolidate.py` 覆盖以上各种写法。

## Alternatives considered

- **只改分钟和小时，`第N秒` 仍读作 N 秒。** 最强理由：秒级差 1 秒无关紧要，旧读法的文档与测试不用动。没采用：同一个"第"在不同单位下读法不同，日后读代码的人要记一条例外；统一读起点规则只有一句话。
- **保持旧读法（`第3分钟` 读作 `03:00`）。** 最强理由：口语里"第3分钟"有时也指"三分钟处"。没采用：模型写"第N分钟"时多是在给区间定位，读成末尾会让找画面的起点越过整段内容；读起点时最坏情况也还在那一分钟内。

## Consequences

- 收益：序数写法的剧情时间落在它所指那一段的开头，写稿 Agent 从这里往后找就能看到对应画面；`第1分钟` 不再越过开头。
- 代价：已经写进旧 `understanding_index.json` 的规范时间不会重算（规范化后存的是 `MM:SS`，原写法已丢），只有新运行或仍保留原写法的索引按新规则读。模型若确实用"第3分钟"表示"三分钟处"，会早一分钟。
