# Agent Note: video-reference 切点改为孤立峰检测加逐帧复核，导出记录检测方式

Status: implemented

接 [[2026-10-02-video-reference-skill]]：那篇里的 `scdet=threshold=10` 固定阈值被本篇取代。

## Problem

真实验证（庆余年 recap，302.66 秒，人工逐帧对照）发现，`measure` 默认的固定阈值 10 会漏掉约三分之一的切点：

- 暗场里 93.04–108.4 秒的 8 个硬切只有 5.1–7.6 分，开场 0–13.56 秒一个也没测到，全片测得 59 个，真值约 87 个。
- 把阈值降到 6–7 也没用：开场 0–1.6 秒是同一个运动镜头（逆光人影从竹林落下），每 0.2 秒就有一个 6–8 分的峰，
  固定阈值会把它数成 7 个切点；后面的急推拉、翻书、箭矢掠过也一样。
- 后果是派生值方向会反：开场段在阈值 10 下是全片最慢（7.84 切/分钟），阈值 7 下又是最快（19.61），真值是最快（23.5）。
  Agent 按"方法方向必须与 derived 一致"写方法，会把开场节奏写反。导出物和 targets 都没记录用的是哪个阈值。
- SKILL.md 只提了叠化会漏，没有让 Agent 核对长镜头；没有理解产物时，Agent 得自己写 ffmpeg 拼图命令才看得到画面。
- 后续真实 API 验证（同一部庆余年，理解产物 + 人工逐帧真值）又发现孤立峰规则看不到的切点：暗场 106.20 秒从打斗切到静物是干净硬切，
  scdet 只给 0.94 分（低于 2 分的记录下限），不在任何待复核窗口，也不在最长 5 个镜头里，文档列出的复核路径都碰不到它。
  288.68 秒的切点在两次测量里分别是 4.00 和 3.989 分，贴着 soft 线时有时无。

## Decision

- **一次解码缓存逐帧分数**：`measure` 用 `scale=320:-2,scdet=threshold=2` 记录所有 ≥2 分的帧，写进
  `reference_measurements.json` 的 `scdet_scores`（不在 `shots`/`loudness`/`derived` 下，不能被引用）。schema 升为
  `video-reference.measurements.v2`。成片 `{size, mtime_ns}` 与缩放设置不变时，只改分数参数不重新解码。
- **孤立峰规则**（`reference_measure.detect_cuts`，检测器名 `scdet-isolated-v1`）：分数 ≥10（`--hard-score`）必算切点；
  ≥4（`--soft-score`）且是前后 0.3 秒内其他帧（相邻一帧除外，它带着切点自己的余像）分数两倍以上才算。
  相邻两帧都过线时并成一个切点。被压下的候选按 0.5 秒间隔合并、各向外扩 0.2 秒，写进 `shots.review_windows`。
- **帧差单侧峰进复核**：scdet 分数是 `min(mafd, |mafd - 上一帧 mafd|)`，前一帧在快速运动时，切点的分数会被减到接近 0。
  同一次 ffmpeg 加 `metadata=mode=print:key=lavfi.scd.mafd` 打出逐帧 mafd，`reference_measure.mafd_peaks` 取单侧峰：
  mafd ≥2，不低于前后 0.3 秒内任何其他帧（相邻一帧除外），且至少是某一侧所有帧的两倍。峰写进测量文件的 `mafd_peaks`，
  不在测得切点相邻帧上的并进 `review_windows`；它们不会自动成为切点。测量 schema 升为 `video-reference.measurements.v3`。
- **新子命令 `frames`**（`reference_frames.py`）：`--review` 逐帧拼出每个待复核窗口；`--longest N` 在最长 N 个镜头里均匀取 12 帧；
  `--span A,B --step S` 是任意时间段的接触表，没有理解产物时用它看片。每格是该时刻**之后的第一帧**
  （`select='gte(t,selected_n*step)'`）。最初用 `fps` 滤镜时，长镜头最后一格取到的是下一个镜头的画面，看起来像漏了切点。
  不用 drawtext，命令打印每格的秒数。页面写在 `U/reference_frames/`。
- **Agent 复核写进 breakdown**：`labels.cut_fixes = {"add": [...], "remove": [...]}`，`remove` 必须在测得切点 ±0.1 秒内，
  `add` 不得与之重复（R1/R2）。check 与 export 先用 `reference_profile.apply_cut_fixes` 得到复核后的切点，所有 `shots.*`、
  段内与音轨内切点密度、`switch_on_cut_share` 都按它重算。有待复核窗口却没写 `cut_fixes` 时给警告；写 `{}` 表示看过、无需改动。
- **导出记录检测方式**：`production_reference.json` 新增 `cut_detection`（检测器、hard/soft、比值、窗口、是否缩放、Agent 增删数）。
  有增删时，`shots.*` 来源的 profile 与 target 的 `provenance` 为 `reviewed`，否则仍为 `measured`。
- 同批修掉验证报告里的几处泄漏扫描小缺陷：
  - `skipped_dimensions` 的原因在 check 阶段就做 R6 扫描。
  - 8 字引文扫描也覆盖相邻两个 ASR 窗口拼接后的文本，以及 `background_research.json` 的全部文字。
  - 实体名加入 `character_details` 别名、≤5 字的 `cultural_notes` 条目，以及资料里《》「」引号中 2–8 字的词。
  - "N 分 M 秒"也认中文数字。
  - 与 fact 描述共有 8 字时，错误单独注明来源是 source_facts。
- SKILL.md：新增"复核切点"一步；`audio_spans` 边界放在声音实际起止处，不放在字幕或旁白块开始处；记录检测器的已知盲区。

## Alternatives considered

- **只把默认阈值降到 5–7**：最强理由是零新代码、一个数字。不选：同一部片里，暗场硬切（5–7 分）与运动镜头的假峰（6–8 分）
  分数区间重叠，没有任何单一阈值两边都对；在庆余年上阈值 5 是 84 对 10 错 3 漏，阈值 7 是 73 对 4 错 14 漏。
- **自己算缩略图帧差或 mafd 基线比值**：最强理由是不依赖 scdet 的"差分的差分"打分。不选：在同一批标注上试过 32×18 缩略图帧差
  和 mafd 相对前 4 帧中位数的比值，急推拉与真切点的特征值同样重叠，还要多解码一路原始帧。
- **把 scdet 记录下限降到 1 以下，或把 2–4 分的孤立峰也列进复核**：最强理由是不加新信号。不选：106.20 秒只有 0.94 分，
  前后一帧 1.16 分，按孤立规则也不孤立；降下限会把每个运动帧都记进缓存。庆余年开场 2–4 分的孤立峰（如 7.8、11.48 秒）按人工真值都不是切点。
- **把帧差单侧峰直接算切点**：最强理由是 Agent 少看几行。不选：庆余年上它在开场急推拉（4.84 秒）和一个运动镜头（19.4 秒）上也成立，
  盘龙的爆闪、烟雾消散同样成立；只进复核窗口时这些误报的代价是多看一行图。
- **只靠 Agent 看图、不做检测改进**：最强理由是人眼最准。不选：87 个切点逐个确认太贵；检测器先把明确的切点定下来，
  Agent 只看被压下的窗口（庆余年 7 个，盘龙 18 个）和最长几个镜头。
- **把复核结果写回 `reference_measurements.json`**：最强理由是消费方只读一个文件。不选：那个文件只由脚本写，按成片身份缓存；
  人工改动放在 breakdown 里，重测不会把它冲掉，也能在 check 里校验。

## Consequences

- 庆余年 recap（同一份人工逐帧真值，87 个切点）：
  - 阈值 10：58 对、1 错、29 漏，11.7 切/分钟。
  - 阈值 7：73 对、4 错、14 漏，15.46 切/分钟。
  - 新规则未复核：82 对、0 错、5 漏，16.26 切/分钟，7 个待复核窗口。
  - Agent 看 `frames --review`/`--longest 5` 后加 3 个切点：85 对、2 漏，16.85 切/分钟。
  - 各段切点密度（开场/铺垫/转折/升级/收束）：真值 23.5/15.7/17.5/15.3/18.3，复核后 21.6/15.7/17.5/15.3/17.1，阈值 10 是 7.8/12.2/12.3/12.9/9.8。
  - 后来的真实 API 验证给出三段逐帧真值：开场 0–14.4 秒 7 个切点（1.64、8.84、9.96、10.80、12.80、12.88、13.56），暗场 88–114 秒
    11 个（含 106.20），160–182 秒 9 个。原来记的"约 7.1 秒遮挡转场漏切"不成立：7.2–7.6 秒是镜头运动，不是切点。
  - 加入帧差单侧峰后（ffmpeg 8.0 本机重测）：切点 82 个，288.68 秒这次是 3.989 分，掉出切点但进了复核窗口；待复核窗口 11 个，
    其中 4 个含漏掉的 5 个真切点（10.80、12.80/12.88、106.20、288.68），新增 4 个窗口里 2 个是真切点、2 个是急推拉和运动镜头（4.84、19.4 秒）。
    补上这 5 个后，三段真值全部对上，无误报。
  - 实测耗时：`measure` 墙钟 15 秒（加 mafd 打印后约 30 秒），`frames --review` 4 秒（11 个窗口 8 秒）。
- 盘龙 recap（4K 动画）：测得 103 个切点，阈值 10 是 52 个，18 个待复核窗口。逐帧抽查了新增的 49 个，除 2 个淡入淡出外都是真切点。
  被压下的真切点主要在快速动作蒙太奇里，例如相隔 0.12–0.36 秒、分数相近的连续切点，靠 review 补。
  加入帧差单侧峰后待复核窗口 37 个：新增的 19 个里逐帧看约 13 个是孤立规则下完全不可见的真切点（多数在 246–257 秒的暗场打斗，
  scdet 3.1–3.9 分），其余是爆闪、烟雾和镜头运动。
- Long Vacation recap：23 个切点（阈值 10 是 22 个），多出的 19.45 秒逐帧确认是真切点。加入帧差单侧峰后多 1 个待复核窗口
  （19.65–20.05 秒，前景遮挡物掠过的跟拍，不是切点）。
- Agent 多一步看图，每次拆片约多 2–5 分钟。这一步只在按需拆片时发生，不碰默认生产路径，也不新增 QC。
- 代价：`reference_measurements.json` 多存几百到几千个分数对和帧差峰（庆余年 162 个分数对、95 个峰）。ffmpeg stderr 每帧多两行
  mafd 打印，只在解析时占内存。`frames` 每行一次 ffmpeg seek。复核窗口变多（庆余年 7→11，盘龙 18→37，LV 0→1），
  Agent 每个窗口多看一行图。检测器仍认不出慢叠化，SKILL.md 已注明。
- 验证报告里另一个问题不归本 skill：被测的 recap 成片在 57.48/57.52 秒的片段衔接处有一帧杂帧，
  说明 cut 阶段没有把片段起点对齐到镜头边界。本篇不处理。
