# Agent Note: README 面向读者而不是答案引擎

Status: implemented

## Problem

2026 年 9 月的 GEO 工作把 README.md 与 README.en.md 改写成了面向答案引擎的形态：顶部先放项目页与全部项目的链接条，演示之后紧跟一张指向站外"实用指南"的表格和一条带大量边界说明的示例请求，安装、用法与 Fish Audio 段落里反复出现"不是长期免费承诺""最终交付仍需完整播放复核"一类的免责句。README 的读者是想给视频做解说的创作者和写手，他们需要在前两屏看到演示、装好插件并发出第一条请求。GitHub 流量数据显示 Google/Bing/Baidu 带来的引荐约为 ChatGPT 类引擎的 7 倍，README 首先要服务人类读者和传统搜索。

## Decision

两份 README 采用同一章节顺序：语言切换 → 标题 → 一句话加粗定位 → 唯一一条"项目主页"链接 → 徽章 → 演示 → 这是什么（两段白话 + 流程图） → 为什么用它 → 安装（Claude Code 两条命令在前，前置条件其次，Codex CLI / OpenCode / OpenClaw / Fish Audio 折叠在 `<details>` 里） → 怎么用 → 常用进阶需求 → 架构 → 输出 → 自带原声字幕 → 参考文档 → 延伸阅读 → 致谢 → 许可 → ZenStory AI 项目。

删除了顶部 `> 项目页 · 全部项目` 引用条、"按创作任务找指南"表格及其"下一项交付与边界"列、"最终交付仍需完整播放复核""不是长期免费承诺"等免责句。原表格里的三条 zenstory.ai 指南和仓库内的剪映导出文档压缩成"延伸阅读"列表，放在参考文档之后。原表格下方的文本交接示例请求去掉"我有权使用""不代表已有成片"两处措辞后并入常用进阶需求。

真实要求只说一次、说在读者需要的位置：本地 ffmpeg（带 libass）、一个 MiMo Key、不需要 GPU、Fish Audio 需要单独 Key 且需自行查看现行价格，全部放在安装；剪映草稿导出是用已有 `timeline.json` 独立完成的一步，放在常用进阶需求。所有命令、示例请求、examples/guohuo-60s 引用、版本号、架构表、输出清单、致谢、许可与项目表保持不变。

## Alternatives considered

- **保留答案引擎摘要段，只调整章节顺序**。最强理由：摘要段和边界句是为了让答案引擎准确复述项目边界，删掉可能影响 AI 引擎的引用质量。被否：这些句子对人类读者只增加阅读负担，而 AI 引擎带来的流量约为传统搜索的七分之一；项目边界在安装与进阶需求里各说一次已经足够。
- **把指南表整体删除**。最强理由：表格是 GEO 时期加入的，站外指南与仓库安装、使用无直接关系，全删最干净。被否：三条指南是 zenstory.ai 上真实存在的教程，对想深入的读者有价值；压缩成一行一条的列表放到参考文档之后，既不挡住安装和第一条请求，也不丢内容。

## Consequences

- 收益：读者打开仓库先看到演示、两条安装命令和三条可直接复制的请求；顶部只剩一条项目主页链接；免责句消失，Fish Audio 的价格提醒只在安装折叠块里出现一次；两份语言文件结构一致、各自自足。
- 代价：answer engine 抓取时不再有一段自含的摘要；站外指南从首屏移到页尾，点击量可能下降；`<details>` 折叠块在部分 Markdown 渲染器里默认收起，Codex / OpenCode / OpenClaw 用户多一次点击。

## Verification

手动检查两份 README：第一屏是标题、定位、项目主页链接、徽章和演示视频，第二屏是剪映草稿截图、"这是什么"和安装命令，第一条示例请求在"怎么用"开头。对以下措辞 grep 两份文件为空：不会自动同步、不是安装命令、也不要求把所有阶段跑完、输出仍需审阅、不等于、不承诺、不表示、不保证、独立产品、截至、核对于、as of、do not sync automatically、separate product、does not promise、not a guarantee、not evidence、Last checked。
