# Agent Note: 长篇写稿、挑画面与验收：名场面清单与通读改稿、短镜头放慢、候选描述与标记、`plan.py qa` 抽查

Status: implemented

## Problem

[[2026-11-25-long-form-recap]] 落地后，长篇挑画面和验收还有几处缺口：

- **短特写用不上**：`plan.py build` 要求每个小句的画面不短于它的配音时长。递东西、看手机这类最贴字面的特写常常只有 1.4–1.9 秒，念一个小句要 2 秒左右，Agent 只能退而求其次选更长、更泛的镜头。
- **候选图只有图**：`frames.py --shots` 不带任何文字，Agent 要自己拿笔记对照每一格；写稿时定的画面意图在候选里也找不到位置；窗口框偏时没有放宽的退路。
- **没有验收手段**：`check.py` 只做物理体检，长篇几百个小句画面对不对得上，没有统一的抽查方式和达标线。
- **结构问题漏报**：原声段互相重叠、钩子原声在正文重放、旁白一句塞太多或太少，都要等看片才发现。
- **局部裁切**：片源只有几个镜头带推广条时，只能整片加大 `recap.crop`。
- **稿子质量靠一遍写成**：规则齐全，但一遍写下来仍常见名场面原声被换成旁白或腰斩、留下平淡的信息交代段；钩子里冒出前面没交代的设定、用套话收尾；挑画面时改出描述画面的句子；为压篇幅一句塞两件事、中途换主语。写完没有通读核对这一步，也没有把旁白连原声台词打成全文来读的工具。

## Decision

- **画面变速**：`video[]` 镜头新增 `speed`（0.5–2，只允许 `audio: mute`），成片时长 =（`out` − `in`）/ `speed`；`_common.timeline_video_spans` 和 `render.py` 的单图、分批两条路径都按它取帧；`export_jianying.py` 也按这套整帧时间线排视频片段，放慢的镜头写剪映变速素材（`materials.speeds` + 片段 `speed`）。`plan.py build` 在镜头短于小句时长、但不短于 0.75 倍时，取整段镜头并写 `speed`，成片仍占满小句时长；再短才报 `ERROR`。
- **候选图**：`frames.py --shots` 新增 `--marks`（写稿时各小句的画面时间，含它的候选标 `*小句号`）、`--notes`（带时间的笔记或转写 JSON，与候选重叠的条目写进该格的 `note`）、`--far`（放宽到更大的时段，窗口外的候选标 `far`）。
- **`plan.py qa`**：在 `build` 之后均匀抽 40 个正文旁白小句（不抽钩子），每个小句一行头、中、尾三帧（带镜头裁切），10 行一张 `sample_<g>.jpg`，`sample.json` 记下对应的小句、整句和成片时点。判断由 Agent 看图做；`long-form.md` 写明达标线（40 个对上不少于 36 个，且无闪帧、画面重复）和必看片段。
- **新增 HINT**（只按时间和字数，不阻断）：同源原声段重叠（钩子与正文重叠时注明）、旁白字数不在 8–40；原声段之间的重叠不再在「画面复用」里重复报；小句画面离 `window` 超过 45 秒才提示（此前 1 秒，有了 `--far` 后同场放宽属正常选择，只在像是另一件事时提醒）。
- **单条 `crop`**：`recap.items[]` 可写 `crop`，覆盖 `recap.crop`，只作用于该条展开出的镜头。
- **写稿参考拆出并加两步**：写稿规则从 `long-form.md` 拆到 `long-form-script.md`（单份参考有 2,500 字符上限）；大纲前先列「名场面清单」，前几名必须进片；写完和挑画面改字后做「通读改稿」，按清单逐条核对。`plan.py script` 打出旁白连原声台词的全文供通读。

## Alternatives considered

- **镜头不够长就向外延展到相邻镜头**——最强理由：不改变播放速度。否：会跨切点出闪帧，正是之前要消灭的问题。
- **允许一个小句接两个短镜头**——最强理由：不变速、信息更多。否：小句和镜头同刻切是这套写法的基础，拆开后要为每个小句再定切点比例，`recap` 格式和挑画面都变复杂；0.75 倍放慢肉眼几乎察觉不到，先用它。
- **把通读核对做成 `plan.py` 的规则检查**（如「回忆」出现次数、旁白复述原声的字面重合）——最强理由：确定、可回归。否：这些是语义判断，关键词规则误报多且违背不做关键词门禁的约定；脚本只负责打出全文。
- **把抽查做成 `check.py` 的自动评分**——最强理由：一条命令出结果。否：画面和字面对不对得上是审美判断，归 Agent；脚本只负责把该看的帧摆出来。
- **「原声停在问句」也做成 HINT**——最强理由：常见结构错误。否：要靠关键词判断，违背不做关键词门禁的约定，留在写稿规则里。

## Consequences

- **收益**：稿子多一遍按观众视角的核对，名场面原声有清单兜底；最贴字面的短特写可以直接用；Agent 挑画面时看得到每格的描述、自己原定的画面和放宽的候选；每版有同一把抽查尺子，前后版本可比；常见结构错误在 `build` 时就提示。
- **代价**：放慢的镜头动作略慢（最慢 0.75 倍）；`--far` 放得太宽会让候选图变大、更难看；多一遍通读改稿要多花一轮 Agent 时间并重配改动句的音、重挑画面；运行时 Python 总行数用到 5,589 / 5,600，再加功能要先删或提预算。
