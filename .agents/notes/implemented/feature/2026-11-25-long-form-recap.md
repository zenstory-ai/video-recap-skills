# Agent Note: 长篇连续解说：`recap` 段 + `plan.py` 展开，`frames.py --shots` 出候选

Status: implemented

## Problem

技能按 1–3 分钟短解说调校（`editorial-craft.md`「约 60 秒成片总切换 2–4 次」）。多集几十分钟的连续解说动辄上百句旁白、几十段原声、几百个镜头，现有能力撑不起来：

- `timeline.json` 只能手写：每个镜头的 `in/out`、每句旁白的成片 `at`、每条字幕都要 Agent 按累计时长自己算，几百段下来几乎必错。
- 没有小句级时长：`tts.py` 只量整句，想做「一个小句一个镜头、镜头和小句同刻切」无从下手。
- 看片只能均匀抽帧：`frames.py` 没有按镜头出候选的模式，Agent 无法在一句旁白对应的时段里逐镜头挑画面。
- 原声段边缘没有对齐原片切点的逻辑（v0.7 的 cut-snap 代码已在 0.8.0 删除），长片里闪帧和半句台词明显增多。
- 画面区间如果只凭文字笔记一次定死、事后才看图，选偏了时候选里没有对的镜头，Agent 容易反过来改旁白迁就画面，旁白变成画面描述。

## Decision

- **`references/long-form.md`**：长篇的素材笔记（有逐场描述先读、没有就用 `frames.py --shots` 逐场写）、大纲（主视角、核心悬念、8–12 段起因→转折→结果）、钩子（一条因果线、不重用正文原声）、写稿（按时间往后、一句一件事、讲故事不描述画面、不复述观众同时看得见听得见的、人物首次出场交代身份、说话人以材料为准、前后句与钩子正文不重复、原声放完整、原声前一句不说破）和 `recap` 段写法。
- **`timeline.json` 的 `recap` 段**由 Agent 写：旁白 `{type: narr, id, seg, source, text, window, shots: [[in, out], …]}`（每个逗号小句一个源区间）与原声 `{type: orig, id, seg, source, in, out}`，可选 `transcripts`、`crop`。
- **旁白的 `window` 锚点**：`window: [a, b]` 是这句讲的事在原片里的时段（按笔记、转写时间框）。挑画面时 `frames.py --shots --window` 只出这一段的候选，换镜头也在窗口里换；窗口里确实没拍到才改那一小句，且改完仍讲故事、不改成描述画面。
- **`plan.py`（配套工具，只依赖 `_common`）**：
  - `voice`：把旁白同步到 `audio.narration[]`（文字没变的保留已测的 `file/duration`），之后照常跑 `tts.py --update-timeline`。
  - `build`：在每句配音里找停顿量出各小句时长，按整帧排每个小句的镜头（在 Agent 给的区间内居中取）和旁白 `at`、按小句出字幕；原声段按转写剪掉超过 1.2 秒的停顿（两边各留 0.3 秒）；每个入出点先在 ±0.3 秒内挪到最安静的 20 毫秒（ffmpeg 解出一小段、标准库算 RMS，不越过前后台词），再在 0.4 秒内贴原片切点（不切台词时贴；入点 3 帧内、出点 0.3 秒内无条件贴：露出下一个镜头的几帧比切掉字幕偏长的尾音更显眼）；帧数向下取整；剪后超过 30 秒的原声段给 HINT；原声段出对白字幕。覆写 `video`、`subtitles` 与旁白 `at`。
  - 只报告不改写：镜头不够长、小句与区间个数不符、取到的画面跨切点 → `ERROR`，退出码 3，不写 `timeline.json`；源时间倒退、同一段画面复用、小句画面出了旁白的 `window`、原声前一句的 `window` 伸进紧接的同源原声段 → `HINT`，不阻断。
- **`render.py` 分批渲染**：超过 48 段镜头时，每 48 段一批、每段用 `-ss` 定位的独立输入只解码自己那一小段（原单图写法要从头解码每集原片、缓存镜头之间的全部画面，几百段的时间线会长时间卡住、占用大量内存），批次以近无损编码出画面+原声中间件、concat 成一段，再作为单镜头时间线交回原有流程做旁白、压低、字幕、包装与响度；48 段以内仍走原单图路径。
- **`frames.py --shots probe.json --window a:b`**：按切点把时段内的镜头（超过 2×`--split` 秒的拆段）各出头、尾两帧，标 `#编号 时长` 和源时间，3 个候选一行。
- **预算**：`SKILL_TOTAL_PY_LOC_BUDGET` 5000 → 5600、`SKILL_MD_CHAR_BUDGET` 4000 → 4300（`plan.py` 约 270 行、`frames.py` +52 行、`probe.py` 改写；SKILL.md 写明 30–240 秒短片与多集长篇两种模式、各走哪份参考，加 `plan.py` 与 `--shots` 入口）。

## Alternatives considered

- **只写长篇指南，Agent 仍手写 `timeline.json`**——最强理由：零代码、零预算。否：几百个镜头的 `at` 靠心算累计，小句时长根本拿不到，错位无法自查。
- **原片时间写旁白、再映射到成片**——最强理由：Agent 面对的证据都是原片时间。否：[[2026-06-16-cut-first-narrate-second]] 已证明映射会丢句、失步。这里反过来：旁白段的画面长度由实测配音决定，`plan.py` 在同一趟里同时算出镜头与 `at`，不存在第二条时间轴，不会失步。
- **`recap` 写成独立的 `recap_plan.json`**——最强理由：不碰 `timeline.json` 结构。否：违背单一总线（[[2026-11-21-atomic-primitives-and-timeline-bus]]），多一份中间状态就要多一套一致性约束。
- **候选窗口按 Agent 初选区间前后放宽几秒**——最强理由：不用多写字段。否：初选偏了，放宽的窗口里同样没有对的镜头；按旁白讲的事框窗口才能保证候选里有它。
- **镜头不够长时自动放慢或向外延展**——最强理由：少一次返工。否：违背「不静默改写」（[[2026-10-02-strict-full-mode-no-silent-rewrite]]），放慢没有 `speed` 字段，向外延展会跨切点出闪帧；报回给 Agent 换镜头更好。
- **把倒序、复用、先说破、「原声停在问句」做成 `check.py` 阻断项**——最强理由：机器能直接挡住常见结构错误。否：`check.py` 只管物理体检；能按时间判断的作为 `plan.py` 的 HINT 足够，问句检测属关键词规则，不做。

## Consequences

- **收益**：Agent 只写内容（旁白、它讲的时段、每个小句的画面区间、原声范围），时间轴由工具算，长片可以一次排对；小句级切镜、原声段贴切点、整帧取整让成片不闪不漂；候选按旁白讲的时段出，画面跟着故事走。
- **代价**：`timeline.json` 多一段 `recap`，`build` 会覆写 `video`/`subtitles`，混用手工改动时要先改 `recap` 再重跑；预算上调 600 行、300 字；长时间线多一次近无损（CRF 10）中间编码，画质损失可忽略、磁盘临时占用约为成片数倍。
