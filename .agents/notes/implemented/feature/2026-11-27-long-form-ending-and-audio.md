# Agent Note: 长篇结尾钩子、配乐与响度

Status: implemented

## Problem

[[2026-11-26-long-form-pick-and-qa]] 之后，长篇解说成片还有三处常见问题，写稿和渲染规则都没覆盖：

- **只讲到中途时结尾太平**：多集剧只剪前几集时，结尾常写成「特训才刚拉开序幕」这类收束句，观众没有看下去的理由；硬写悬念又容易编出后面没发生的剧情，或用「敬请期待」这类套话。
- **原片配乐和 BGM 打架**：原声段带着原剧自己的配乐，再垫一条 BGM 两路音乐叠在一起；只在原声段把 BGM 压低或静音，BGM 一段段断开再淡回，听起来像每次从头播。
- **解说和原声不一样响**：TTS 旁白和原片对白的响度没有对齐，常见旁白比原声小 4 dB 左右；`plan.py voice` 每次重写 `audio.narration[]`，手调的旁白 `gain` 会丢。

## Decision

- **结尾钩子**：`long-form-script.md` 大纲一节写明只讲到中途时的结尾：先把最后一场收住（话说完、事有结果），再用 1–3 句旁白抛出前文已埋下、还没解决的悬念，落在具体问题上；只用讲过的事，不编后面的剧情，不用套话。
- **配乐与响度**：`long-form.md` 新增第 5 节：
  - 原声段先用人声分离工具分出对白轨，混回视频另存一份作为源；
  - 解说和原声各抽几段用 `ffmpeg -af ebur128` 量，差 1 dB 以上就调；
  - BGM 选纯音乐，全片一条连续循环，原声段和旁白下都不压低（`mix.duck.bgm_under_narration` 不低于 BGM `gain`），比人声低约 18 dB；
  - 曲子比片短时先交叉淡化接长。
- **`recap.narration_gain`**：`plan.py voice` 把它写进每句旁白的 `gain`，重跑 `voice` 不丢。
- **通读与验收补充**：通读清单加「长定语开头改成先说人再说事」「旁白开头不重复刚听完的原声词组」；`plan.py qa` 的对上标准加「画面是这个小句那一刻，不是下半句的画面」。

## Alternatives considered

- **原声段只压低 BGM、不分离原片配乐**——最强理由：不用额外工具，渲染器的 ducking 现成可用。否：原剧配乐仍在，两路音乐叠加；BGM 一断一续听着像重播，实际成片里这一点最刺耳。
- **把人声分离做进 `render.py` 或新脚本**——最强理由：一条命令出片。否：分离要 PyTorch 和模型权重，违背运行时只用标准库和 `ffmpeg` 的约定，运行时 Python 预算也只剩个位数行；作为可选的外部前处理写进参考即可。
- **按 LUFS 自动给旁白定 `gain`**——最强理由：不用人工量。否：要在 `plan.py` 里调用 `ffmpeg` 逐段测响度，增加耦合和行数；一个全局系数加一次测量就能对齐，交给 Agent。

## Consequences

- **收益**：前几集的长篇有了不编剧情的结尾钩子；成片里 BGM 连贯、不和原剧配乐打架；解说和原声听感一致，`gain` 不会被 `voice` 冲掉。
- **代价**：分离对白会连原片音效（脚步、环境声）一起去掉；需要宿主另装分离工具，分离几集要额外十几分钟；BGM 音量建议值（低约 18 dB）偏轻，具体还要看曲子听感；运行时 Python 总行数到 5,594 / 5,600。
