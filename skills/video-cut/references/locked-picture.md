# 锁帧画面重建（不是默认剪辑模式）

已有采用的镜头起止帧，只需回原片取宽、换构图，且不允许自动改剪点时使用。默认 `cut.py <video>` 的秒级计划和句界保护保持不变。

```bash
python scripts/cut.py --picture-plan /path/picture_plan.json \
  --work-dir /path/new-picture-candidate
# 只改轨/预检，不渲染：再加 --normalize-only
```

也可直接调用 `scripts/picture_plan.py <plan> --output-dir <new-dir> [--plan-only] [--crf 18]`。
输出目录必须是新目录，失败不能覆盖已有结果；产物是一份候选无声画面资产，不是成片，也不是版本晋升记录。

## 最小输入

```json
{
  "artifact": "picture_plan",
  "schema_version": 1,
  "fps": "30000/1001",
  "canvas": [1280, 720],
  "tail_frames": 0,
  "sources": {
    "episode-a": {"path": "/media/episode-a.mp4", "sha256": "<完整文件SHA-256>"}
  },
  "shots": [{
    "id": "reaction",
    "source_id": "episode-a",
    "source_frames": [240, 288],
    "output_frames": [0, 48],
    "crop": {"x": 160, "y": 0, "width": 960, "height": 540},
    "window": [160, 90, 960, 540]
  }]
}
```

坐标仅为示例，必须根据当前源尺寸与构图填写，不是可以照抄的中心裁切默认值。

- 所有帧区间为**半开区间**，来源为 `v:0` 解码后的显示帧顺序；不是关键帧序号。
- 来源需同帧率、零起点、实际 CFR、无旋转、方形像素、BT709或未标色彩的SDR。工具完整探测实际 PTS，不能只凭文件名或声明 fps 通过。VFR、隐式变速、混合帧率、已标记的其他色域/传递函数暂不支持，会失败；不会把P3、HDR或BT601标签静默改成BT709。
- 输出区间从0连续排列。缺省每段源/输出帧数相等；允许显式重复与重排来源，不会吸附镜头或句界。已有采用的快慢放必须提供下面的逐帧映射，不从时长差或浮点 speed 猜帧，也不自动补定格掩盖坏接点。
- crop 的位置与尺寸为偶数源像素；动态水平取景通过 `crop.x_by_frame` 给出**每个局部输出帧**的偶数 x 值，数量等于段长，首值等于 `crop.x`。不接受稀疏关键点、表达式或隐含插值。
- window 为 `[x,y,width,height]`；画窗尺寸为偶数，位置可为奇数。crop/window宽高比仅允许不超过0.2%的像素取整误差，不允许拉伸适配。
- `tail_frames` 必须显式填写；大于0表示纯黑占位画面，**不是片名卡**。最终交付仍需独立包装。

## 已采用的快慢放：显式帧表

在 shot 增加 `source_frame_by_output`，按每个**局部输出帧**列出绝对源帧号。例如源 `[240,246)`，输出 `[0,4)` 可明确写 `[240,242,243,245]`；输出 `[0,8)` 可写 `[240,240,241,242,243,244,245,245]`。

列表必须等长于输出区间、全部为区间内整数、单调不减。允许显式丢帧/重复帧；不接受反序、光流生成或未声明插帧。首尾未被采用的源帧不强行补入。帧表须来自作者决定或实测：从创作工具的实际输出导出帧映射，不能由速度比率推算。

动态 crop 仍以输出帧为准；同一个源帧重复两次时，两次可有不同的 x。归一化结果保留 `mapping_kind`，缺省 identity 继续走旧过滤链与 v1 算法，显式表使用 v2。完整源 span 的实际 PTS 仍逐帧检查；重采样后再将所有输出帧的平面校验值与源帧表比对，失败不发布。

实现使用 FFmpeg `shuffleframes`；为凑齐缓冲块产生的 dummy padding 不允许出现在帧表中，也不是交付画面。内存随 `max(源段帧数, 输出帧数)` 的解码帧体积线性增长，大分辨率长变速段需注意内存，失败保留诊断不降级为近似重建。此路径只处理画面，**不自动变速原声或重映射字幕**；后续应配对与该输出钟匹配的采用音轨。

## 实际验证与输出

先完整核源帧钟与内容身份。seek只用于加速，裁切后逐个比较 `showinfo` 的原始 PTS 与声明源帧切片，包含内部帧；不是只查首尾或片段秒数。动态x以平衡分支表达式执行，避免大量逐帧样本造成深层表达式。

画面顺序为 crop → Lanczos scale → RGBA → canvas pad → BT709有限范围YUV420P。RGB垫底使奇数y不被4:2:0自动取整；这不表示色彩无损。未标记的SDR源采用FFmpeg默认解码解释，源标签原样记录，不能当作已测源色彩。

- `picture_plan.validated.json`：标准化计划，明确帧数、全量crop样本与黑尾语义。
- `picture_map.json`：每镜头源 span 实际PTS、逐输出源帧/PTS、构图、源身份、输出身份与实际媒体检查；显式变速另存重采样前后平面校验值及 `buffer_frames`。
- `picture_run.json`：`PLANNED` / `PICTURE_RENDERED` / `FAILED`；检查源/计划在执行中变化。
- `picture.mp4`：仅成功验证后发布的独立**无声画面资产**；没有声音、字幕、标题或真实片名卡。
- `chunks/`、`logs/`：本候选的重建中间文件与实际命令证据，不是交付视频。

现有 `adopted-packet-copy` 只支持同一输入容器里的AAC，不能把本无声资产直接当成已配好音轨的成片；这不是交付件，音轨配对、混音与包装都不在本能力范围内。正常速度观看、剧情完整性、是否吸引人不会因这些技术检查自动通过。
