# 字幕与画面包装工序

永远先把画面、切点、旁白和混音彻底锁定，再去加字幕动效或画面包装。任何字体特效和边框都只是锦上添花，绝不能拿来掩盖剧情跳脱、切点闪帧或人声打架。

日常交付优先使用内置的 ASS 字幕烧录。只有当用户明确需要逐句定制排版、字卡动效或透明前景动画时，才把 Remotion 等代码渲染器作为**单个项目的可选外挂环节**引入，不要把特定前端框架、专有字体或某种固定黄字样式写死成核心流水线依赖。

## 推荐制作顺序

1. **先出素片母版**：渲染出不带花哨包装的锁定母版，确认画面切点、旁白节奏与原声留白不再改动。
2. **按实际语音切分字幕**：基于配音阶段产出的真实语音时间线切分字幕条（cue）——送交 TTS 合成的文本块应保持整句连贯，而展示在屏幕上的字幕条则按单行阅读宽度拆短。
3. **关键样帧抽检**：先在片头、高光亮背景、暗场背景、人物特写和全片最长字幕处各抽一帧，核定字号、安全边距、描边粗细、阴影深浅以及是否需要加半透明底板。
4. **合成透明前景层**：渲染出带透明通道的完整包装前景层，叠加（overlay）到锁定母版上；合成时音轨直接流复制（`-c:a copy`），合成后核对帧率、总时长与音轨数据包未被改写。
5. **原速通看终审**：按正常倍速从头到尾播放最终成片，逐处排查字幕是否遮挡人脸、跳字、断行怪异、首尾帧闪烁或接点留有残影。

若项目自备了外部代码渲染器，由该项目自行将透明包装层合成到锁定母版上，本技能不内置逐帧前景合成命令。带渐显或入场动画的片名卡必须渲染完整帧序列，不能只截最后一帧静态图硬贴上去。

## 静态包装图层 `packaging_layers.json`

像固定边框、顶部标题栏、角落台标这类全片位置不变的静态图片，无需动用外部代码渲染器逐帧生成，直接在 `work_dir` 下编写 `packaging_layers.json` 即可在合成阶段一次叠加完成：

```json
{
  "canvas": {"width": 1080, "height": 1920},
  "layers": [
    {"name": "frame", "path": "/abs/frame.png", "rect": {"x": 0, "y": 0, "width": 1080, "height": 1920}}
  ],
  "template": {"id": "brand-frame", "version": 2}
}
```

- `canvas` 宽高必须与成片实际画布完全一致，否则合成前直接报错；每个图层的 `rect` 必须完整落在画布内部，图片会缩放到 `rect` 指定尺寸并保留透明通道。
- 画面叠加从底到顶的顺序固定为：原片硬字幕遮罩 → 静态包装图层（按 `layers` 数组先后顺序）→ ASS 解说字幕 → 最终分辨率缩放。
- 静态包装图层会同步写入 `timeline.json` 的 `image` 轨，导出剪映草稿后可在剪映里单独选中或调整边框图层。
- `assembly_manifest.json` 的 `assembly_settings.video_filters.packaging_layers` 会记录每张叠加图片的路径与 `{size, mtime_ns}`。
- 编排器根据项目绑定的 `packaging` 模板自动生成该文件时会打上 `written_by` 标记；用户自己手写的 `packaging_layers.json` 不会被编排器误删。至于带渐入渐出或关键帧动画的动态包装，仍由项目级代码渲染器自行合成。

## 审美与克制原则

好包装靠的是全片统一、一眼看清、贴合剧情气质的干净版式，而不是把特效堆满屏幕。先定好一套稳定的主字体、字色、描边阴影和克制的入场效果；底板、外框、醒目花字与点缀音效只在真正需要帮观众看清信息、拎出剧情拐点时才出手。单张静态截图好看，不代表整支视频动起来舒服。
