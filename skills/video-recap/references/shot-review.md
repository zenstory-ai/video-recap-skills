# 成片内部短镜头与密集切镜复核

`shot_review.py` 是只读检查工具：只扫描并报告可疑切点，不改动剪辑计划、不触发边界吸附、不重编码视频，也不会自动删掉短镜头。即使剪辑计划里的某段区间长达十几秒，原片自身在这段区间内部仍可能夹着 2 帧、12 帧或 14 帧的碎反打镜头；因此必须直接检查**本轮实际渲染出来的视频文件**，不能只看计划表上的片段时长。

```bash
# 默认按 --threshold 0.35 扫描：
python3 scripts/shot_review.py edited_source.mp4 --output review/shot_review.json
# 当剪辑输出视频与同目录 .meta.json 齐全时，可绑定剪辑计划一起核对：
python3 scripts/shot_review.py edited_source.mp4 --plan clip_plan_validated.json \
  --output review/shot_review_planned.json
# 怀疑低反差画面漏检时，可另跑一轮低阈值扫描作对照（0.08 仅为高灵敏度示例，并非必跑的第二遍）：
python3 scripts/shot_review.py edited_source.mp4 \
  --threshold 0.08 --output review/shot_review_sensitive.json
# 画面带黑边或固定包装框时，传入实测主画面区域的像素坐标，保持阈值不变做对照：
python3 scripts/shot_review.py packaged.mp4 --roi "$X" "$Y" "$WIDTH" "$HEIGHT" \
  --output review/shot_review_picture.json
```

`--roi` 只在检测阶段裁切送入滤镜的画面区域，不修改原视频文件或剪辑计划。坐标按 FFmpeg 自动旋转摆正后的原生像素填写，而非播放器按 SAR 拉伸后的显示尺寸；矩形必须完整落在画布内部。报告中的 `scene_roi` 会记录本次实际扫描的矩形区域，未指定时为 `null`（全画布）。排查黑边或包装干扰时，应先用 `--roi` 排除黑边和标题花字区，再微调召回阈值，并同时保留全画布扫描报告作对照，严禁靠缩小扫描区域来掩盖闪帧。若主画面窗口位置随镜头切换而变化，单个固定 ROI 只能代表该区域的检测结果，不能据此宣称全片画面已检查完毕。

## 精度与校验规则

- 工具通过 `ffprobe` 完整解码收集每一帧的真实 PTS，scene 滤镜直接使用整数 PTS 与滤镜时基对齐，不靠跳转（seek）后的浮点 `pts_time` 反推帧号。
- 帧号从 0 起算，区间采用左闭右开 `[start_frame, end_frame)`，片头首镜与片尾末镜同样纳入检查。可变帧率（VFR）视频会直接累加每一帧的精确分数 PTS 时长，不用平均帧率乘以秒数估算。
- 默认召回条件为：单个镜头不超过 **1 秒**，或 **2 秒内出现至少 4 个切点**。短镜头帧数上限默认按实测帧率换算（`round(fps × 1 秒)`），不写死固定帧率；需要按固定帧数卡控时可用 `--max-short-frames` 显式覆盖。此外，`summary.flash_slivers` 会单独挑出时长 `<= 0.20s`（约 1–5 帧）的极短残镜闪帧，供 `cut.py` 与 `final_qc.py` 作为硬阻断项拦截；其余 `0.20s–1.0s` 的短镜头则保留在 `short_spans` 中供动态审片复核，不搞一刀切误杀快节奏反应镜头。
- `0.35` 是默认的 scene 初筛阈值。对于带大片黑边、包装边框占比高或暗场低反差的画面，固定阈值会系统性漏报；**某个阈值下报出零候选，绝不等于成片真的没有闪帧。** 应先用一段已知含碎镜头的片段校准阈值，并保留每一轮扫描报告，不得靠调高阈值把候选清零后直接宣称“通过”。反过来，压低阈值也会把闪光、急推拉和包装动效一并召回。
- 未传入 `--plan` 时，所有候选的来源一律记为 `UNKNOWN`。传入 `--plan` 时，工具会先核对计划中的片段列表、渲染参数是否与 `edited_source.mp4.meta.json` 完全一致、源文件 `{size, mtime_ns}` 是否未变、输出视频是否存在且非空；任一失配立即报错退出，绝不猜测或混用过期文件。报告中的 `plan_binding.path` 仅如实记录本次绑定的计划文件路径。
- 落在帧对齐后的 EDL 拼接点前后 1 帧以内的候选，仅标记为 `EDIT_JOIN_CANDIDATE`。落在片段内部的候选虽会标出所属 `clip_id` 与推算的原片秒数，但来源仍记为 `UNKNOWN`——在没有单独核对原片切点前，不能武断认定它是原片自带的切镜。
- 遇到时间戳缺失、末帧时长无法覆盖到流末尾或解码报错时，扫描会直接中止。报告文件在扫描启动时先写入 `SCANNING`，中途失败则改写为 `SCAN_FAILED`，绝不让上一轮遗留的成功报告冒充本轮结果。此外，输出路径只能指向新文件或已确认为本工具格式的旧报告，严禁覆盖视频源文件或剪辑计划文件。

## 候选复核与修复流程

对召回的每一处候选，都要按原速回看前后 0.5–1 秒画面，核对人物表演、动作起落、台词完整性与原片切点；凡未经原速回看的候选，一律保持 `NEEDS_DYNAMIC_REVIEW` 状态。排查时先对照原片画面与取景参数：同一个原片镜头中途切换裁切窗口（crop）或遇上闪光灯，也会打出高切点分数，两个高分点之间夹着的那几帧未必真是一段独立短镜头。

修改剪辑计划并重新渲染后，用完全相同的参数重跑一遍扫描，对比候选列表的变化，再按原速播放确认接点已经顺畅；对于刻意保留的短促反应镜头，逐一确认看感即可，不必因为时长短于 1 秒就机械删改。确认属于无意义的残帧或碎反打后，回到 `clip_plan.json` 删掉整段碎镜头，或恢复同源连续画面；若属于有信息量但被切碎的反应镜头，则回原片外扩入点或出点把反应留完整，严禁用定格画面凑时长、加转场遮掩，或绕过剪辑计划直接修补成片文件。

## 修补碎镜头时的取景规范

修补碎镜头时，必须同时核对原片自身的镜头切换与输出画面的裁切窗口（crop/window）。严禁只为把相邻两帧的 scene 分数压下来，就对接点前后的几帧画面做突兀的局部放大或平移，导致人物表情被裁切、画面忽然发糊或构图跳动。正确做法是：先在原片自然切点两侧，为前后两个镜头分别设定稳定、清晰、主体完整的取景框；相邻镜头的景别与裁切比例不必强求一致，但跨切点的画面比例变化、人物落位和视线方向必须在原速播放下自然顺眼。修复后保存同一输出帧号的修前/修后邻帧对比图，并一并复核声音衔接、字幕同步、总帧数与播放速度。切点候选数量减少或分数下降，只代表滤镜读数变了，不代表肉眼看感已经修好；在没有按原速回看成片前，报告中的 `normal_speed_review` 始终保持 `NOT_CHECKED`，且不会自动写回 `clip_plan_validated.json['qc']`。
