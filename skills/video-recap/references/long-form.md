# 长篇连续解说（多集、几十分钟）

把多集剧情剪成 20–60 分钟「一口气看完」：按原片时间顺序讲完整条故事线，旁白段与完整原声对手戏交替。30–240 秒短片的切换次数、人名上限不适用；`recap` 段与 `plan.py` 短片也能用。

## 1. 素材笔记

- 有外部逐场描述（分镜/剧本稿：场次、画面动作、说话人）先读它作 `MEDIA_NOTES.md` 底稿，再抽拼图核对；没有就按集逐场写：时间段、地点、人物、画面事实（`frames.py --shots` 拼图看完再写）、关键台词（标说话人）。
- 只记看到听到的；推断单独标出，写稿时不当事实用。

## 2. 大纲与写稿

- `EDIT_PLAN.md` 先定主视角、贯穿全片的核心悬念，正文分 8–12 段，每段写起因 → 转折 → 结果和名场面原声。
- 开头钩子 20–35 秒：一条因果线（人物处境 → 冲突 → 原声 → 悬念），第一句就是旁白；钩子原声不用正文已用的段落，钩子说过的正文开头不再说。
- 正文按原片时间往后讲，不回头、不预告。每句旁白一件事，12–35 字，按停顿加逗号；讲谁、为什么、结果，像说书人，不描述画面，也不复述观众同时看得见、听得见的。
- 只写素材里有的事；人物用名字，第一次出场交代身份；说话人以笔记、转写标的为准，拿不准就不把话安到具体人头上。回忆、梦境要说明。
- 原声段放完整：问要有答，表白要有结果，冲突有回击；开头不是缺上文的回话，结尾话说完。剪掉停顿后一般 8–20 秒，最长约 30 秒；更长就只留改变局面的那几句往来，其余用旁白带过。
- 垫半句、让半句、接半句：原声前一句交代谁对谁、在什么情况下开口，但不说出原声里的话或结果；后一句接住尾音讲反应或后果，不复述。前后句不讲同一件事。1–4 句旁白接一段原声，两者约各半。

## 3. `recap` 段与 `plan.py`

在 `timeline.json` 写 `recap`（`plan.py build` 据此覆写 `video`、`subtitles` 与旁白 `at`；可选 `crop` 套到每个镜头，如裁掉源片烧录字幕）：

```json
{"transcripts": {"s1": "media/ep1.transcript.json"},
 "items": [{"type": "narr", "id": "n1", "seg": "hook", "source": "s1", "text": "他刚丢了工作，回老家却撞见当年的对头", "window": [10.0, 36.0], "shots": [[12.0, 14.6], [30.2, 33.0]]},
           {"type": "orig", "id": "o1", "source": "s1", "in": 40.1, "out": 52.6}]}
```

- `window` 写这句讲的事在原片里的时段（按笔记、转写的时间，讲哪几句台词前后就框哪段），画面只在这里挑。旁白按逗号切成小句，每个小句一个 `shots` 源区间（同一镜头内、够长）。
- 挑画面用 `frames.py --shots --window` 看这个时段的候选：原选对就不动，换镜头也在窗口里换；窗口里确实没拍到这件事才改这一小句，改完仍是讲故事、事实不变，不改成描述画面。
- 流程：`plan.py voice` → `tts.py --timeline timeline.json --update-timeline` → `frames.py <源> --shots media/probe.json --window <window>` 看候选定 `shots` → `plan.py build timeline.json --probe media/probe.json` → `render.py` / `check.py`。
- `build` 量每个小句的实测时长排镜头与字幕，原声段剪掉超过 1.2 秒的停顿、入出点贴原片切点。报 `ERROR`（镜头不够长、小句数不对）就改 `recap` 重跑；`HINT`（倒序、画面重复、画面出了窗口、原声前一句的窗口伸进这段原声即先说破）逐条复核。
