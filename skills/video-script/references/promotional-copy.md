# 宣发标题、花字与文案返修

仅在用户要求策划宣发选题、撰写标题/封面字/发布文案、精修花字，或将外部模型产出的文案回填进工程时使用本指南。普通解说写稿或微调剪点时不额外跑这一步。

## 先定这条片子拿什么勾人

从**当前这支短片**（而不是整部剧的百科简介）里拎出一个最扎眼的看点：谁在什么绝境下做了什么狠决定、付出了什么代价，观众点进来到底能看爽哪一幕或揪心哪一秒。先在片子里找准兑现这句承诺的具体画面和原声秒数，再动笔写标题。同一批切片可以分别卖身份反差、当场打脸、暗中护短、笑点反差或悬疑伏笔，别把每一条都硬套成同一种“惊天反转”模板。

网感标题与花字的三条铁律：

1. **摆处境与动作反差，不堆空泛形容词**：用“葬身火海三年的白月光，挽着亲哥回来让我叫大嫂”“百亿股权签字当天，亲妹越过我全权委托给外人”这种带身份、带物件、带动作的短句直给冲突，绝不用“高能预警”“虐恋情深”“命运齿轮转动”等毫无信息量的套话。
2. **两行常驻标题写清“谁卡在什么局里”**：上行立反常处境或身份错位，下行亮出当场反应或代价，不用生僻人名和设定黑话劝退路人，也不提前剧透片尾还没演到的胜负。
3. **花字只做“点穴”，不做复读机**：花字只用来点破角色嘴硬背后的潜台词（如嘴上说“大嫂好”、花字点出`旧情难藏`；高烧抓手喊胡话、花字点出`本能不会说谎`），绝不把正在念的台词再抄一遍。

需要结合外部行情做案例调研时，按剧集发行状态区分信息源：

- **已播剧**：查该剧在社交平台上的真实高赞评论、二创高频切片和观众争议焦点，再看当前这支短片能不能接住这个话题。
- **未播新剧**：根据本片自带的人物反差与戏眼提炼受众卖点，参考近期同题材爆款的切入角度，不要假装新剧已经有全网讨论度。

引用外部案例时写清发布账号、链接、发布日期、采集日期、核心手法及可借鉴之处。单条视频播放量、整剧主话题热度、多端聚合数据要严格分开写；哪怕某条爆款数据再高，也不能直接断定“全靠某一句标题带火”。历史调研过时就重新核实；查不到确切数据时宁可留空，离线方案直接写明“仅依据片内现有素材推演”。

## 发给外部模型的文案任务包

批量打磨多条切片时，按共用的剧情段落与看点分组打包，保证上下文充足，但每条成片各自独立交付。直接用精炼的 Markdown 任务包描述即可，不必额外拼装视频时间轴文件。每条切片列清五项内容：

1. **当前工程版本**：工程路径、对应成片文件和待渲染改动；已有版本号时原样沿用。
2. **片内实拍内容**：正片结束时间、冲突起因与兑现结果、当前保留的镜头列表、原声与旁白字幕，并标明时间戳对应哪一版成片。
3. **现有包装文字**：两行常驻标题、各处花字及起止时间、时空角标；已有封面字与发布文案时一并附上。
4. **本轮允许改动的范围**：写明哪几层文字可以动，以及哪些剪点、字幕、旁白、配音、字体样式和片尾必须锁死不动。
5. **证据边界提醒**：标出角色嘴上说的狠话与实际发生事实之间的落差、本片尚未演到的结局、拿不准的专有名词及尚未核实的粗略时间码。

任务包末尾可附上这段直接可用的指令模板：

> 先用两句话讲清这支短片凭什么让路人停下手指、看完能得到什么情绪回报，再给出主推文案；需要备选方案时按不同切入卖点区分，别只换几个近义词。两行常驻标题、封面字和发布标题各司其职。花字与时空角标逐条列出修改前后对比、成片时间位置及片内画面/台词依据；没必要加字的地方宁可留白。在仅阅读工程文件与字幕稿时，给出的时间窗只算提案，不要声称已经肉眼审片。如果某个观感硬伤只能靠重剪镜头或调整混音解决，请单独拎出来说明，别试图靠堆砌花字遮丑。

## 各文字层的职责边界

| 层 | 核心职责 | 实操铁律 |
|---|---|---|
| 常驻标题 | 让划过来的陌生观众三秒看懂人物困局与本片爽点/痛点 | 用身份、动作和代价替代陌生人名与设定黑话；绝不提前宣布片内没拍到的输赢 |
| 封面字 | 在静态封面帧上钉死最抓人的一处矛盾 | 别把两行常驻标题原封不动抄上去；字面意思必须跟所选封面帧的表情动作严丝合缝 |
| 发布标题 | 补齐人物关系前情、争议话题或互动钩子 | 别把旁白全文贴进文案区，也别编造片子里没说过的角色台词 |
| 花字 | 点破言行反差、潜台词或关键观察点 | 绝不复读原声或旁白字幕，不挡脸和手部关键动作；画面拥挤时优先撤掉花字 |
| 时空提示 | 交代回忆/当下、地点转换或画外音来源 | 严格跟着画面切点走，别跟着提前进场的跨场旁白抢跑 |
| 对白/旁白字幕 | 忠实打出耳朵听得见的台词与解说 | 不属于宣发包装改字范围，严禁拿花字去覆盖或顶替正常字幕 |

“却”“不是……而是……”并非绝对禁词，但只要画面本身没有需要帮观众纠偏的误解，就直接写人物干了什么、换来什么后果。角色当场发誓不等于事情已经办成，单方面眼神拉丝不等于双向奔赴，挨打流血也不等于当场毙命。批量复核多条切片时，重点排查各条的卖点切口和句式是不是撞车，不要把共用了一两个过场镜头但戏剧落点完全不同的片子混为一谈。

## 将定稿文案回填进工程

- 回填前先核对任务包所基于的工程是否仍是最新底板；若期间已经重调了剪点、换了镜头顺序、重配了语音或改了字幕时间，必须先把新文案重新对齐到最新版本，绝不能拿旧工程全文直接覆盖，更不能光看文件修改时间就盲目替换。
- 先把当前工程复制出一份新候选副本，只改动本轮拍板采纳的条目；凡是没明确说要改的文字、ID、时间码、坐标位置和显隐开关一律保留原样。**提案里没提某条花字，代表保持原样，绝不代表删掉它**。提案中写 `notes=[]` 可以表示“本轮不新增批注”，但要是直接写进完整工程文件就会清空整条花字轨，因此动工前必须先把“保留、新增、替换、删除”四类动作逐条列清。
- 新增花字或调整时空角标起止时间时，必须对照当前成片的真实画面、台词落音和帧率换算入出点：恒定帧率（CFR）直接核准帧号，可变帧率（VFR）按真实显示时间戳（PTS）反查对应帧号。外部提案里只写到小数点后三位的秒数只算粗略建议，不能直接当成已对齐的帧级切点。
- 严格使用现有包装工程的字段结构，不要另起炉灶私造新轨道：常驻标题、花字、时空角标各自写回原本所属的图层，时间范围最终换算为整数半开区间的帧号（而非浮点秒数）；工程内指向源素材、字幕文件和样式表的路径引用原封不动。封面字与发布文案单独留在宣发交付物里，不塞进视频渲染配置。
- 回填落盘后做前后 diff 复核：逐项确认该改的词已到位、未改的图层零误伤、所有花字时间窗均未越过正片结尾。若项目配有静态同步或校验工具，先跑通校验；用户只要求修改工程文件时到此收工。若继续渲染成片，必须在出片后肉眼检查新字是否按时出现、有无遮挡人脸或加重阅读负担，绝不能把“改完 JSON 工程”等同于“成片已经验收通过”。
