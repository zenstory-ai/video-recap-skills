# 写稿前补充调研指南（可选）

动笔写稿前先看 `work_dir/background_research.json` 是否已经存在。如果仅凭现有的视频理解索引还摸不清作品名称、人物关系、故事前提或专业概念，可以先做一次轻量补充调研，把核实过的信息写进该文件。**新写入的资料不会自动重跑或改写已有 VLM / ASR 产物**；本技能仅将它当作 `context-only` 的写稿背景与建议型评审参考，当前镜头里发生了什么仍以时间线上的画面与原声证据为准。调研并非必经步骤；手头没有检索工具、处于离线环境或搜不到可靠来源时，直接跳过即可。

## 工具选择

用当前环境里顺手的任意检索方式即可：

- Codex / Claude 内置的联网搜索或网页抓取工具；
- 用户已配好的浏览器自动化或页面读取工具；
- 在外部浏览器手动查清后，把关键事实整理进 JSON；
- 直接采用用户口头交代的剧情背景或项目目录内已有的资料文档。

## 通用流程

1. 从 `--context` 参数、源文件名或用户提问里拎出片名、角色名等检索词。
2. 每次只搜 1–3 个最卡脖子的事实问题，别把时间耗在漫无目的的考据上。
3. 只记对写解说真有用处的干货：谁和谁是什么关系、故事卡在什么前提下、世界观核心设定、当前这一集演到哪一步、关键术语是什么意思。
4. 将核实后的结果写入 `work_dir/background_research.json`。
5. 严格区分背景资料与 `vlm_analysis.json` / `asr_result.json` 的职责：前者帮你叫准人名、搞懂前因，后两者证明当前画面里真演了什么、说了什么。
6. 若搜不到可靠信息，立即跳过调研并回到当前创作阶段；要是还没定创作方案，先写好 `recap_story_plan.json` 与 `visual_audio_board.json`，再按当前所处的 `full` 或 `cut` 阶段写 `narration.json` 或 `clip_plan.json`。

## 按视频类型搜索策略

### 短剧 / 电视剧

| 搜索关键词 | 目标字段 |
|-----------|---------|
| `{作品名} 剧情 介绍 人物` | synopsis, characters |
| `{作品名} 人物 关系` | characters |
| `{作品名} 第{N}集 剧情` | episode_context |

### 电影

| 搜索关键词 | 目标字段 |
|-----------|---------|
| `{电影名} 剧情 简介` | synopsis |
| `{电影名} 影评 解读` | cultural_notes |

### 纪录片 / 科普视频

| 搜索关键词 | 目标字段 |
|-----------|---------|
| `{主题} 背景 知识` | worldbuilding |
| `{核心概念} 解释` | synopsis |
| `{主题} 最新 进展` | cultural_notes |

## 写入格式

写入 `work_dir/background_research.json` 时，只填查实的字段；没查到的字段直接省略，不要填 `null` 或空字符串。

```json
{
  "synopsis": "...",
  "characters": {
    "角色名": "简介或关系"
  },
  "worldbuilding": "...",
  "episode_context": "...",
  "cultural_notes": [
    {"item": "...", "explanation": "..."}
  ]
}
```

## 异常情况处置

| 场景 | 处理 |
|------|------|
| 没有浏览器 / 搜索工具 | 跳过调研，回到当前创作阶段 |
| 搜索无结果 | 换一组关键词重试一次，仍无结果则回到当前创作阶段 |
| 检索结果互相打架 | 只采信用户明确交代的上下文，或画面与 ASR 原声能直接印证的信息 |
| 资料里带了后续剧透 | 仅拿来认准人物关系，除非用户明确要求，否则绝不在解说里提前剧透后文结局 |

**铁律**：背景资料只用来补齐前情上下文，绝不能拿来顶替 `vlm_analysis.json` 与 `asr_result.json` 里的当场画面和原声证据。
