# 生产能力边界与验收原则

本仓库的通用技能负责看片提取信息、落实剪辑与写词方案、合成配音并导出成片；针对单部剧集或单个账号的定制参数与排期管理，统一放在你自己的项目目录里维护。各技能的具体功能与命令行参数见对应的 `SKILL.md`。

## 通用核心、按需适配与单项目数据的分工

| 层级 | 职责边界与处理方式 |
|---|---|
| **剪辑/解说通用核心** | 提取画面与台词信息、定主线与挑镜头、分段配音合成、原声与 BGM 混音分工、字幕对轴、画框字幕渲染及成片质检。这部分集中在主技能 `video-recap` 内完成；按需调用的 `video-reference` 只负责把现成优秀成片拆成剪辑参考，不参与日常做片流程。 |
| **按需启用能力** | 自托管 TTS 地址与音色、指定画面区域（ROI）切点检测、静态贴图叠加、剪映草稿导出。只在用户显式传参时开启，不在普通剪辑任务里增加额外的必填项。 |
| **项目或操作者事务** | 成片交付清单、文件体积压缩、多平台上传发布、网盘同步、临时目录清理。这些事务不进通用技能，也不内置后台常驻进程或自动删文件逻辑。 |
| **单项目私有数据** | 批次编号、集数清单、特定剧集的裁切画窗/帧率、专有字体与台标、片尾固定时长、特定音色 ID 与混音音量。统一放在你自己的项目配置或计划 JSON 里，不写死成通用默认值，也不混入公共文档示例或测试数据。 |

判断标准很简单：**如果某个数值、路径或特殊处理只对某一部剧成立，就不写进这个仓库的核心代码。** 文档示例统一使用一眼能看出的演示参数（如非标准画幅、合成音频），单元测试数据从各自独立的常量生成，不写死真实商业项目的帧号、数据包计数或内部编号。

## 三类检查各管一摊，不能互相替代

- **客观技术指标**：时间戳范围、文件大小与修改时间、帧数、解码是否完整、成片真峰值音量等，由脚本自动核对，不合格直接报错停下。
- **辅助排查线索**：分段语音转写（ASR）、切点得分候选、抽帧拼图和剧情线索表。它们用来帮人快速定位画面和台词位置，本身有精度上限和漏报盲区；输出文件里会如实标明精度来源（粗分段 / 按字数比例估算 / 音量校准）以及未检查项（`NOT_CHECKED`）。
- **人工看片判断**：开头抓不抓人、演员反应留得够不够、配乐合不合适、最终成片原速看下来顺不顺耳。**JSON 结构合法或自动化测试全绿，不代表成片好看好听。**

## 脚本自动拦截的硬伤与人工复核项

如果质量要求只写在提示词里，多轮改片后很容易走样。本仓库把可量化的底线直接写成脚本里的报错拦截与核对记录：

- **默认不擅改文稿**：解说词一旦塞不下时间窗（在允许倍率内温和提速后仍装不下），合成前直接报 `no_safe_fit` 退回改词或扩窗，不会让 TTS 擅自删字或硬切尾音凑时长。
- **声音模式显式隔离**：标准解说（`narration`）与纯原声配乐混音（`--audio-mode source-mix`）分开运行，切换模式必须换用新工作目录，防止旧配音串进原声成片。
- **混音音频全程可核对**：`_placed_*.wav` 按本轮输入重新生成，并与写入磁盘的 `timeline.json` 逐段核对；只改外层画框或字幕时仍会重新混音并编码 AAC（若需要完全不重编码、直接复制已有 AAC 音轨，请固定使用 `v0.6.2`）。
- **粗转写时间不冒充精校字幕**：15 秒一段的粗转写 ASR 与估算秒数不会拿来冒充逐句对齐的字幕。
- **必保画面与原声提前核对**：Agent 在 `clip_plan.json` 的 `required_evidence` 里标出不能剪丢的关键问答与反应，脚本在对齐边界后、正式渲染前逐条检查。
- **台词收尾留气口与片尾淡出**：切出对白时默认预留最多 `0.30s` 反应和呼吸气口（中间遇到硬切点则收在切点前），片尾自动对原声与配乐做 `350ms` 淡出，避免声音突然断开。
- **扫描真实成片切点，拦住极短闪帧**：`cut.py` 剪出画面后自动解码扫描切点，遇到拼接点附近 `<= 0.20s`（1–5 帧）的碎闪帧（`flash_frame_sliver`）或镜头吸附与完整台词冲突（`shot_speech_conflict`）直接报错停下；原片单镜头内部自带的闪光灯或雷电则记为 `SOURCE_INTERNAL_FLASH_ADVISORY`，同时注明“未检出候选不代表完全没有闪帧”。
- **硬伤报错与语境提醒分开处理**：旁白没写完的残句（`incomplete_sentence`）、半句打断原片台词（`interrupts_source_sentence` / `unsafe_source_handoff`）和残留示例占位符（`placeholder_leakage`）一律在配音或合成阶段直接拦截；而受粗分段 ASR 或题材语境影响的情况——旁白收口落在粗转写对白区间内且后续 3s 无停顿点（`unsafe_source_release`，合成端按 `bounded_release` 平滑回升音量）、片头超过 `2.5s` 无对白/旁白（`weak_cold_open_silence`）、连续超过 `5.0s` 无对白/旁白留白（`excessive_dead_air`），以及已有具名角色资料却写出“黑衣男子”等外貌泛称（`generic_character_label`）——统一记为不阻断渲染的 `warning` 提醒复核，避免误拦台词前提前让位、无声冷开场、长动作戏或路人角色。
- **出片质检默认严格把关（`--require-final-qc` 默认开启）**：只要 `final_qc.json` 里检出阻断问题（包括 `assembly_qc.json` 的混音报错和 `shot_review.json` 的闪帧报错），命令就会以非零退出码停下（仅显式传 `--no-require-final-qc` 时改为只记录不阻断）。

至于故事和表达层面的要求——解说词有没有画面与原声支撑、有没有脑补原片没拍的情节、有没有占掉本该留给演员原声的重头戏（`validate.py` 只检查与对白的时间重叠，不读 `visual_audio_board.json`）、开场钩子在后文有没有兑现、有没有空洞套话（脚本只拦示例占位符泄漏）——不做机械打分，由 `video-recap` 里的 Agent 自检和出片后原速看片把关；不要把 `validate.py` 通过当成故事已经讲好。

## 五个常见翻车情况

- **指标全过但故事断了**：把交代起因的镜头剪丢了，哪怕帧率、响度、台词停顿全都合格，观众照样看不懂后面为什么突然翻脸。
- **拿粗转写硬当逐句字幕**：15 秒一段的 ASR 能把台词转出来，但角色真正开口可能在第 6 秒；直接按字数平摊时间打字幕，声画一定错位。
- **更新了缓存但混音还在读旧音频**：新跑的 TTS 写进了缓存，但混音脚本读的还是工作目录里的旧 WAV；光看 `tts_meta.json` 发现不了成片声音没变。
- **长片段中间夹着几帧废镜头**：剪辑计划里选的是连续 12 秒，但原片在这 12 秒中间切过一个几帧的碎反打；光查计划表上的片段时长查不出来。
- **改了计划没重渲就交片**：只改了 `clip_plan.json` 却没重跑渲染，把工作目录里上一轮留下的旧 `output.mp4` 当新成片交出去。

## 两层回归验证

1. **第一层（成片重建与规格核对）**：给定源视频与解说文稿，重新生成画面、字幕与画框包装，逐项核对镜头顺序、输出总帧数、字幕切入帧、实际字号坐标与片尾淡出。不同平台的编码器存在细微差异，不要求整段 MP4 字节完全相同。
2. **第二层（新素材盲测审查）**：只给源视频、做片要求与修改意见，不给参考答案，跑完后按独立问题清单逐项核查。盲测题库与具体商业项目的对应关系只留在私有测试库中，不放进开源仓库。
