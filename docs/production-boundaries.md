# 生产能力边界与验收原则

通用技能负责素材证据、创作交接、配音和渲染；单个项目的配置与交付管理由调用方维护。功能与命令行见各 skill 的 `SKILL.md`。

## 核心、按需适配与项目数据

| 类别 | 处理方式 |
|---|---|
| 剪辑/解说核心 | 素材证据、故事与镜头决定、完整语音、原声/BGM 分工、字幕时机、按选定风格渲染及实际成片检查。这是六个生产 skill 的职责；按需的 video-reference 只把成片拆成制作参考，不参与生产。 |
| 按需适配 | 自托管 TTS 端点/音色、锁帧取宽、静态包装图层、剪映导出。用户显式选用才执行；不为简单剪辑制造额外必填资料。 |
| 项目或操作者任务 | 交付批次登记、打包容量限制、分发渠道、共享盘同步、磁盘清理。不进入核心 skill，也不以默认后台任务或删除器的形式出现。 |
| 项目数据 | 任务编号、清单条数、固定画窗/帧率、字体/logo、片尾长度、配音声线与混音数值。放在调用方自己的配置或计划 JSON 里，不成为通用默认值，不写进公共样例与测试金标。 |

一个判断口径：**如果某个数值、路径或流程只对一部剧成立，它就不属于这个仓库。**
文档样例应使用明显合成的数值（非目标画幅、非目标帧率），测试夹具从自己的常量推导，
不引用任何真实交付的帧号、包数或回归编号。

## 三类验收，不能互相冒充

- **机械事实**：时间、身份、范围、文件、解码等，可以由程序作确定判断，失败即阻断。
- **证据辅助**：转写、场景候选、截图、故事证据链。它们能定位问题，但有能力与覆盖边界，
  产物必须标注精度（粗窗 / 估计 / 校准）与未检项（`NOT_CHECKED`）。
- **创作判断**：是否吸引人、反应是否动人、配乐是否合适、实际听感与观看体验。
  JSON 格式合法或单测通过都不构成这一层的证据。

## 交付规则要成为执行器会遵守的约束

很多交付规则如果只写在给 Agent 看的说明里，返修后无人复核。补强的方向是把它们落成
执行器的行为与可复核的产物：

- 文本不被改写：默认路径就不删改稿子。文本装不下窗口时回到创作，不让 TTS 自动删减文案或强行变速。
- 声音归属显式化：解说（默认）与原声混音（`--audio-mode source-mix`）两条路径各自独立，切换要用新工作目录，不沿用对方的产物。
- 放置层可核对：`_placed_*.wav` 由本次输入重建，并与序列化后的时间线对账。只改画面或包装也会重新混音并重编码 AAC；需要音频包不变的用 v0.6.2。
- 字幕时机不冒充精度：粗窗与估计的时间不当精字幕用。
- 必保证据前置：Agent 声明必须保留的原片时刻，工具在吸附之后、渲染之前核对。
- 成片内切点回归：扫实际渲染文件，不只查 EDL；候选为零不是证明。
- 最终 QC 可选 fail-closed：显式开启后，阻断项存在时不打印完成。

下面这些规则目前没有机器检查，只写在 `video-script` 的 Agent 自检清单里：旁白是否有证据支撑、
有没有编情节、有没有占用留给原声的拍（lint 只核对与对白的时间重叠，不读 `visual_audio_board.json`）、
承诺是否兑现、有没有套话（去 AI 味检查只拦破折号和示例占位，其余只报告）。返修后没有程序复核，只能靠重做
自检和人看成片；不要把 `validate.py` 通过当作这些规则已满足。

## 必须保留的反例

- 关键前提被删，视频技术完全合格，但故事仍不成立。
- 粗窗 ASR 能转出全文，但第一个字实际晚于窗口起点；粗窗不是精字幕。
- 新 TTS 缓存正确，实际混音仍引用旧 WAV；再核 metadata 也救不了。
- EDL 区间很长，里面夹着十几帧无关反打；只看 EDL 段长会漏报。
- 计划已更新但尚未 render；不能把旧成片显示为修订完成。

## 验证设计

第一层：给源素材与旁白，重建画面/字幕/包装，核镜头顺序、输出帧、字幕起落、
实际字号位置与末段。编码不同不要求整段 MP4 逐字节相同。

第二层：不给最终答案，只给源片、任务与修改要求，产出后再用独立保留的问题集审查。
问题集与任何真实项目的映射只存在于私有基准目录，不写进通用实现分支。
